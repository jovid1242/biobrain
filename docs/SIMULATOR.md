# SIMULATOR — минимальный spiking-движок (Milestone 2)

Код: `src/biobrain/snn/`. Цель — корректный, измеряемый, воспроизводимый движок, на котором в следующих
milestones можно честно проводить эксперименты. Обучения здесь нет: топология, веса и параметры неизменны
в течение прогона.

## 1. Модель

Безразмерный current-based LIF с мгновенными (delta) синапсами и фиксированной задержкой. Порог θ = 1 —
единица всех потенциалов и весов, покой 0.

```
на шаге t (dt, по умолчанию 1 мс), одинаково в обоих режимах:
  1. утечка            v ← v·α,  α = exp(−dt/τm)
  2. синаптический вход v ← v + Σ w(e) по спайкам, испущенным на шаге t − d
  3. внешний вход      v ← v + w_in, если на шаге t есть внешнее событие
  4. рефрактерность    если t − last_spike ≤ ref: v ← v_reset
  5. спайк             если v ≥ θ: v ← v_reset, last_spike ← t, события целям на t + d
```

Почему delta-синапсы. Без входа потенциал только затухает к 0 и не может пересечь порог, а между
событиями изменение точно равно `v·α^k`. Поэтому event-driven режим может не трогать нейрон, к которому
ничего не пришло, и получить тот же результат. Это и есть предмет сравнения режимов. Цена упрощения:
ток мгновенный, нижней границы потенциала нет (см. `M2_LIMITATIONS.md`).

Все параметры и их классификация (OBSERVED / DERIVED / ASSUMED / TUNED) — `docs/ASSUMPTIONS.md`, раздел M2.

## 2. Веса и знаки

```
w(e) = sign(e) · gain · f(synapse_count(e)) / mean_по_всем_15.1M_рёбрам( f )
f ∈ {linear, sqrt, log1p, clipped(c)}
```

- `synapse_count` — OBSERVED (M1).
- Нормировка DERIVED: одна константа на преобразование, посчитанная по всему коннектому. Поэтому одна и та же
  пара нейронов получает один вес в любом подграфе, а `gain` означает средний |вес| ребра коннектома в
  единицах порога.
- Знак — таблица по нейромедиатору (ASSUMED). По умолчанию ACh +1, GABA −1, glutamate −1; dopamine, serotonin,
  octopamine 0 («не быстрый синапс»); нет предсказания — 0.
- Источник нейромедиатора: `neuron` — аннотация `top_nt` пресинаптического нейрона (один нейромедиатор на
  нейрон, как у Shiu 2024); `edge` — преобладающий класс предсказаний ребра (если их нет, берётся метка нейрона).
  На всём коннектоме эти источники совпадают лишь на 79.6 % рёбер.
- Рёбра с весом 0 удаляются из графа симуляции и учитываются в `meta.removed_zero_sign`.

## 3. Два режима одной модели (`engine.py`)

| | time-step | event-driven |
|---|---|---|
| обновление | все N нейронов каждый шаг (`v *= α`, плотные операции NumPy) | только нейроны, получившие вход на шаге |
| утечка | умножение на α каждый шаг | ленивая: `v·α^k`, k = шагов с последнего обновления; таблица α^k |
| рефрактерность | список спайков последних `ref` шагов → удержание | проверка `t − last_spike ≤ ref` у затронутых нейронов |
| входы с задержкой | кольцо из d плотных накопителей по N (`bincount`) | кольцо из d списков пакетов `(targets, weights)` |
| агрегация пакета | `bincount(minlength=N)` — O(N + E) | `sparse`: `np.unique` — O(E log E), без O(N) на шаге; `auto`: при E > N/8 один O(N) `bincount` + маска |
| порог | по всем N | по затронутым |

Ленивая утечка корректно учитывает рефрактерность и `v_reset ≠ 0`: если рефрактерный период закончился после
последнего обновления, потенциал считается от `v_reset` с момента конца периода.

## 4. Очередь событий: варианты и выбор

| вариант | оценка | решение |
|---|---|---|
| Python-объект на событие (heap) | миллионы объектов на шаг при плотной активности; нарушает правило «никаких объектов на синапс» | отвергнут без реализации |
| priority queue | нужна только для произвольных (непрерывных или разных по рёбрам) задержек | не нужна: задержка фиксированная и целая |
| кольцевой буфер пакетов (ED) | O(1) Python-объектов на шаг; события лежат numpy-массивами | **выбран** |
| кольцевой буфер плотных накопителей (TS) | d × N × 4 байта; естественен для режима, который и так O(N) | **выбран** |
| агрегация пакета | измерена (`tools/aggregation_microbench.py`) | см. ниже |

Микробенчмарк агрегации (NumPy на Apple M5): при N ≥ 10k сортировка (`np.unique`) быстрее плотного `bincount`,
пока событий E ≤ N/10. При E ≥ N/5 быстрее плотный вариант: в 1.6 раза у границы и в 33 раза при N = 50k и
E = 1M (1.6 мс против 52 мс). При N = 1k плотный быстрее уже с E = N/10. Поэтому у event-driven два варианта: `sparse` (чистый, без O(N) работы на шаге) и `auto`
(переключение на плотную агрегацию). Обновления нейронов в обоих вариантах ограничены затронутыми нейронами.

## 5. Память

| компонент | time-step | event-driven |
|---|---|---|
| топология | indptr int64 (N+1) + indices int32 (E) | то же |
| состояние синапсов | веса float32 (E) | то же |
| состояние нейрона | v float32 + last_spike int32 = **8 байт** | + t_last int32 = **12 байт** |
| очередь | d × N × 4 байта | пик ожидающих событий × 8 байт |
| прочее | — | таблица α^k (≤ 70·τm/dt значений) |
| входной поток | indptr int64 (steps+1) + int32 на событие | то же |
| инструментация | счётчики на шаг и на нейрон | то же |

16 байт на нейрон из задания не понадобились: 8 и 12 байт достаточно. Изменение t_last на int16 не делалось,
потому что ломает прогоны длиннее 32,767 шагов.

Peak RSS меряется в отдельном процессе, который загружает готовые массивы сети и входа из кэша и только
симулирует. Из него вычитается peak RSS пустого процесса с теми же импортами (`empty_process_rss.json`).

## 6. Инструментация (без FLOPs)

| счётчик | определение |
|---|---|
| `neuron_updates` | нейроны, чьё состояние вычислено на шаге (time-step: N каждый шаг) |
| `skipped_neuron_updates` | N·steps − neuron_updates |
| `spikes` | испущенные спайки |
| `synaptic_events` | доставки «спайк × исходящее ребро» — по одному сложению веса; это и есть synaptic operations |
| `external_events` | внешние входные события |
| `refractory_occupancy` | доля нейрон-шагов в рефрактерности (точно из спайков) |
| `wall_s` | только основной цикл; подготовка отдельно (`process.setup_s`) |
| `phases` | время по фазам шага — только в профилировочных прогонах (`profile=True`) |

FLOPs не считаются: они не определены однозначно для этого кода. Энергия не выводится из счётчиков.

## 7. Эквивалентность режимов

Для одной и той же сети, входа, seed и config сравниваются спайки по шагам, по нейронам и растры (строгое
равенство) и финальные потенциалы. Допуск по потенциалу объявлен до прогонов: float64 1e−9, float32 1e−4 в
единицах порога. Источник расхождений — только порядок операций при утечке (α·α·… против α^k) и округление.

Итоги (`M2_RESULTS.md`, раздел 2): растры идентичны в 80 из 80 сравнений на реальных подграфах, число спайков
совпадает в 220 из 220 пар бенчмарков. В float64 режимы совпадают спайк в спайк и на 40,000 шагах. **В float32 длинные прогоны
расходятся:** time-step отходит от эталона float64 на шаге 3,349, а event-driven float32 остаётся идентичен
эталону все 40,000 шагов. В рекуррентной сети одно перевернувшееся из-за округления пересечение порога
размножается, поэтому сравнение режимов в float32 корректно только на коротких горизонтах. Для длинных прогонов
эталон — float64.

## 8. Входы (`inputs.py`)

Входной поток генерируется заранее: CSR по шагам, отдельный поток случайных чисел. Так оба режима получают
идентичные события, а генерация не попадает во время цикла.

- `poisson`: каждый шаг каждый допустимый нейрон получает событие с вероятностью `rate`.
- `burst`: то же в окне `burst_on` каждые `burst_period` шагов.
- `pulse`: каждые `pulse_every` шагов синхронно `pulse_fraction` нейронов.
- `sparse_pattern`: фиксированный пространственно-временной паттерн, повторяемый каждые `pattern_every` шагов.

Внешнее событие весом 2θ вызывает спайк, если нейрон не рефрактерен (ASSUMED).

## 9. Режимы активности и калибровка

Правила записаны до калибровки (`metrics.py`). Пробный вход: Пуассон 1 % на шаг 300 мс, затем 300 мс тишины.

- **SATURATED:** частота при входе ≥ 50 % максимума, ограниченного рефрактерностью, или частота в последней
  трети тишины ≥ 10 % максимума.
- **DEAD:** спайков при входе < 1.05 × внешних событий (рекуррентная передача добавляет < 5 %) и тишина в
  последней трети.
- **STABLE:** всё остальное. Флаг `self_sustained` означает, что активность сохраняется без входа.

Калибровка: сетка gain 0.003…3 (19 значений, логарифмически), 3 seed. Baseline — геометрическая середина
самого широкого непрерывного диапазона, где все seed STABLE. Если такого диапазона нет, baseline не
назначается и это публикуется.

## 10. Подграфы и null-топологии

- `subgraph.py`: `expand` (жадное расширение от seed-нейрона по числу синапсов, вложенные 100 ⊂ 1k ⊂ 10k ⊂ 50k)
  и `neuropil` (home neuropil из M1). Manifest содержит sha256 списка нейронов и рёбер; при загрузке
  подграф пересобирается и сверяется.
- `nulls.py`: degree-preserving (in/out-степени) и reciprocity-preserving (степени + число взаимных пар).
  Каждый пресинаптический нейрон сохраняет свой набор выходных весов. В M2 это только проверка
  инфраструктуры, выводов о топологии нет.

## 12. Компилируемый backend (Milestone 2.5)

Код: `src/biobrain/snn/compiled.py`, вызов — `engine.run(..., backend="numba")`. Модель та же, NumPy-движок
не менялся. Numba 0.67.0, CPU, один поток, без `fastmath` и `parallel`. План и критерии — `docs/MILESTONE25_PLAN.md`,
итоги — `docs/MILESTONE25_REPORT.md`.

**Тот же порядок арифметики, что в NumPy.** Каждое ядро повторяет операции своего NumPy-режима, поэтому результат
побитово совпадает: растры, счётчики, финальные потенциалы, записи потенциала — в float32 и float64. Это
проверяется тестами и экспериментами, а не предполагается.

- **time-step:**
  - `v·α` в типе состояния на каждом шаге;
  - синаптический вход копится по нейрону в float64 в порядке событий (как `np.bincount`) и приводится к типу
    состояния один раз;
  - затем внешний вход, удержание рефрактерности, порог.
- **event-driven:**
  - та же ленивая утечка `base·α^k` по той же таблице;
  - те же суммы float64 в том же порядке событий. Для этого спайки шага сортируются по возрастанию (без
    выделения памяти: вставками для коротких списков, иначе поразрядной сортировкой по 9 бит).

**Без выделения памяти в цикле.** Все буферы создаются до вызова ядра. Тест сверяет счётчики аллокаций Numba NRT
на 50 и 800 шагах: они одинаковы (18 на прогон time-step, 31 на прогон event-driven — это аргументы вызова).
Ядро возвращается досрочно только при записи растра, если буфер может переполниться: вызывающий код
увеличивает буфер и продолжает с того же шага.

**Варианты накопления событий в event-driven** (все дают одинаковый результат):

| вариант | как | память на событийную часть |
|---|---|---|
| `touched` (по умолчанию) | обход строк CSR спайкнувших нейронов при доставке; накопитель float64[N] + список впервые затронутых целей; обновляются и очищаются только они | d×N int32 (id спайков) + N×(8+1+4) |
| `dense` | тот же накопитель + один проход O(N) по флагам на шаге со входом | d×N int32 + N×9 |
| `copy` | как `touched`, но события (цель, вес) копируются в кольцевой буфер в момент спайка | d×E×(4+4) + N×13 |

Вариант по умолчанию выбран правилом, объявленным до исследования: наименьшее геометрическое среднее времени
по ячейкам «размер × вход» (`results/milestone25/experiments/check_compiled_event_driven.json`).

**Ядра без ветвлений.** Первая версия ядер (с условными переходами) тратила 12–16 нс на обновление нейрона в
event-driven. После замены условий на выборки (select) с той же арифметикой — 2–3 нс. Результаты первой версии
сохранены (`*_v1_branchy.json`). Для event-driven детали реализации оказались важнее, чем для time-step.

**Профилирование скомпилированного кода.** Таймеры фаз внутри ядер — `clock_gettime_nsec_np` (≈ 7 нс на
вызов, до 7 вызовов на шаг). Включаются только в режиме `profile`.

**Память time-step отличается от NumPy:** накопитель входа — float64 (d×N×8 байт вместо d×N×4 у NumPy). Так
сохраняется порядок округления NumPy. Состояние нейрона то же: 8 байт (TS) и 12 байт (ED).
