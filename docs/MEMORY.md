# MEMORY — сколько стоит граф FlyWire в памяти

Все числа — из `results/memory/memory_benchmark.json` (`biobrain bench-memory`, commit `d47ea8e`, Apple M5,
16 GB RAM, Python 3.14, NumPy 2.5). Каждое представление строилось **в отдельном процессе**.

Граф: **139,255 нейронов, 15,091,983 рёбер (пар), 54,492,922 синапсов**.

## Как мерили

- **structure** — точный размер буферов представления (для Python-объектов — `tracemalloc`).
- **RSS после построения** — прирост RSS процесса сразу после построения. Исходные массивы читались без memmap и
  освобождались. Для представлений, которые при построении создают много временных массивов (varint,
  квантование), RSS остаётся выше structure: macOS-аллокатор не сразу отдаёт память системе. Поэтому основная
  метрика — structure, RSS — это наблюдение процесса.
- **peak** — максимальный прирост RSS за построение и тесты доступа (рабочая память).
- **lookup** — выборка соседей и весов случайного нейрона (10,000 запросов, из Python). Время включает
  накладные расходы интерпретатора (~0.3 мкс), поэтому это сравнение представлений между собой, а не абсолютная скорость.
- **propagate** — один «шаг спайков»: 1 % нейронов (1,392) спайкует, все их исходящие синапсы доставляются
  (`bincount` по целям). В среднем **143,676 синаптических событий** за проход.
- **full scan** — один проход по всем рёбрам.
- Python-объекты строились на 1,000,000 рёбер и **экстраполированы линейно** на 15.09 M.

## Компромиссы (RESULT → INTERPRETATION)

1. **Сам граф маленький.** CSR всего мозга занимает 87 MiB, это 1 % от бюджета 8 GB. Бюджет будут расходовать
   не рёбра, а рабочая память алгоритмов и будущие состояния нейронов и синапсов.
2. **Представление важнее языка.** Python-объект на ребро в 21–42 раза дороже CSR: 1.8–3.7 GiB на граф.
   Правило «никаких объектов на синапс» подтверждено измерением. Таблица «как скачано» в RAM тоже в 15 раз дороже.
3. **COO проигрывает CSR и по памяти, и по скорости.** Поиск соседей в несортированном COO требует прохода по всем
   рёбрам: ~4 мс против 0.3 мкс, то есть ~10,000× медленнее. Шаг спайков в 21–31 раз медленнее.
4. **Сжатие окупается только на хранении.** Delta+varint вдвое уменьшает граф (3.0 против 6.1 байта на ребро), но
   шаг спайков в **6.4 раза** медленнее, полный проход в **15 раз**, а кодирование требует ~2 GB рабочей памяти.
   На 87 MiB такая экономия не нужна. Она станет интересной, только если граф придётся уместить в память
   нейроморфного чипа или микроконтроллера. zstd даёт 3.3 байта на ребро для диска и передачи, без произвольного доступа.
5. **Region-local ids не стоят сложности.** Лишь **47.6 %** рёбер остаются внутри home neuropil, поэтому
   экономия всего 14 % (5.2 против 6.1 байта на ребро).
6. **Memmap — хороший вариант по умолчанию.** Открытие стоит 0 MiB RSS, страницы подгружаются по мере обращения.
   Скорость шага спайков та же, что в RAM, но одиночный lookup из Python в 3 раза медленнее из-за накладных расходов memmap.
7. **CSC нужен не всегда.** Он добавляет 116 MiB (8 байт на ребро) ради входящих рёбер за O(1). Для
   распространения спайков достаточно CSR. Входящие связи понадобятся пластичности (STDP) и анализу,
   решение принимается в Milestone 3.
8. **Кандидат на сжатие весов для SNN:** uint8 в логарифмической шкале (1 байт, ≤ 7 % ошибки на ребро). Потеряна
   ли при этом значимая динамика — **гипотеза**, её проверяет Milestone 2/3, а не этот замер.

## Оценка для Milestone 2 (гипотеза, не измерение)

Граф в CSR — 87 MiB. Состояние LIF-нейрона (потенциал, порог, счётчик рефрактерности, время последнего спайка)
укладывается в 8–16 байт × 139,255 ≈ 1–2 MiB. Один пластичный след на синапс в float16 — ещё 29 MiB. Значит,
весь мозг с одной пластичной переменной на ребро укладывается примерно в **~120 MiB** без рабочей памяти
симулятора. Проверить измерением в Milestone 2.

Скорость «одного шага 1 % нейронов» в NumPy — 0.5 мс, примерно 280 млн синаптических событий в секунду при
плотной выборке. Это не скорость симулятора: там добавятся обновления нейронов, очереди событий и пороги.
Реальную цифру даст бенчмарк event-driven против time-step в Milestone 2.
