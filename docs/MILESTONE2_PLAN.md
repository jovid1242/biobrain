## 1. Что строим и чего не строим

Строим **один минимальный LIF-движок с двумя режимами исполнения** (time-step и event-driven) поверх реальных
связных подграфов FlyWire, с инструментацией с первого дня: счётчики операций, память по компонентам,
время, peak RSS. **Не строим:** обучение любого вида, pruning, эволюцию, задачи, UI, биологически точную муху.

## 2. Модель (baseline; каждый параметр классифицирован в `docs/ASSUMPTIONS.md`)

Безразмерный current-based LIF с мгновенными (delta) синапсами, шаг dt:

```
v ← v·α                      α = exp(−dt/τm)          (утечка к покою 0)
v ← v + Σ входов, пришедших на этом шаге (синапсы с задержкой d шагов + внешний вход)
если нейрон рефрактерен (t − last_spike ≤ ref): v ← v_reset
если v ≥ θ: спайк; v ← v_reset; last_spike ← t; всем постсинаптическим целям — вход через d шагов
```

θ = 1 (единицы порога). Вес ребра: `w = sign(pre) · gain · f(synapse_count) / mean_all_edges(f)`,
`f ∈ {linear, sqrt, log1p, clipped}`; знак — настраиваемая таблица по нейромедиатору; задержка — фиксированная,
настраиваемая. Выбор именно delta-синапсов: между событиями потенциал меняется по точной формуле
`v·α^k`, поэтому event-driven режим может обновлять нейрон только когда к нему что-то пришло — это и
есть предмет сравнения.

## 3. Два режима одной модели

| | time-step | event-driven |
|---|---|---|
| обновление нейронов | все N каждый шаг | только получившие событие (ленивое `v·α^k`) |
| очередь входов | кольцевой буфер плотных накопителей (d × N) | кольцевой буфер пакетов (targets, weights) |
| агрегация входов | `bincount` (O(N + E)) | сортировкой (O(E log E)), без O(N) работы на шаг |
| общее | один config, одни веса, один входной поток, один seed, одинаковый порядок операций |

Эквивалентность: одинаковые спайк-растры (строгое равенство) и `max|Δv|` ≤ допуска (float64: 1e−9;
float32: 1e−4 в единицах порога). Расхождения считаются и публикуются, а не скрываются.

## 4. Подграфы (связные, воспроизводимые, с manifest)

- **expand** — жадное расширение от seed-нейрона центрального мозга по суммарным синапсам с уже выбранным
  множеством: 100 ⊂ 1k ⊂ 10k (⊂ 50k опционально), вложенные.
- **neuropil** — нейроны с данным home neuropil: PB (102), SPS_R (968), LO_R (9,864) — проверка, что выводы
  не артефакт способа выбора.
- Manifest: версия данных (sha256 store manifest), метод и параметры, seed, число нейронов/рёбер/синапсов,
  состав по суперклассам и neuropil, sha256 списка нейронов и рёбер, связность (WCC/SCC).

## 5. Эксперименты

1. **Тесты корректности** (раздел 17 задания), включая крайние случаи.
2. **Калибровка усиления (TUNED, воспроизводимая процедура):** для каждого размера — развёртка `gain` по
   логарифмической сетке при фиксированном входе (Пуассон 1 % на шаг 300 мс, затем 300 мс тишины), 3 seed;
   классификация DEAD / STABLE / SATURATED по заранее записанным правилам; baseline = геометрическая середина
   интервала, где все seed STABLE. Если такого интервала нет — это результат, а не повод подбирать руками.
3. **Эквивалентность** TS vs ED на 100/1k/10k при нескольких уровнях активности, float64 и float32.
4. **Benchmark matrix:** {100, 1k, 10k} × {TS, ED} × активность {0.1, 0.5, 1, 5, 10, 25, 50 %} × 3 seed,
   1,000 шагов (1 с модельного времени), каждый запуск в отдельном процессе (peak RSS). Плюс паттерны входа
   (burst, синхронный импульс, разреженный временной паттерн) на 1k и 10k. 50k — только если 10k стабилен и быстр.
5. **Чувствительность** на 1k: transform, знак глутамата, знак модуляторов, источник знака (нейрон/ребро),
   τm, задержка.
6. **Null-контроль** на 1k: REAL, DEGREE-PRESERVING (веса переносятся с пресинаптическим нейроном),
   RECIPROCITY-PRESERVING — только проверка, что движок запускает разные топологии через один интерфейс;
   научных выводов о топологии не делаем.
7. **Профилирование** фаз шага; при узком месте в Python — `docs/PERFORMANCE_PLAN.md`.
8. **Оценка полного коннектома** (RAM, операции, время) по измерениям — помечена ESTIMATE, запуск не делаем.
